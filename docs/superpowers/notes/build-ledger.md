## Rulings
Ruling: use an in-place feature branch `feat/hf2ollama` instead of a worktree — master only holds docs so nothing is at risk, and absolute paths stay simple — a worktree move later is trivial.
Ruling: `fit::Machine` derives `Debug, Clone, PartialEq, Serialize, Deserialize` — required by Task 5 — none if wrong, one derive line.
Ruling: in Task 13 the GUI defines `BackendRequest` (enum: `Core(Command)`, `Search(SearchQuery)`, `ModelInfo(String)`, `ListInstalled`, `ShowInstalled(String)`, `DeleteInstalled(String)`, `TestConnection(String)`) and `UiEvent` (enum: `Job(JobEvent)`, `SearchDone(Result<Vec<ModelSummary>, String>)`, `ModelInfoLoaded(Result<ModelInfo, String>)`, `InstalledLoaded(...)`, `InstalledDetails(...)`, `DeleteDone(...)`, `OllamaStatus(Option<String>)`, `ConnectionTest(Result<String, String>)`). `Backend::spawn` returns `(Sender<BackendRequest>, Receiver<UiEvent>)`. Later GUI tasks may extend these enums — plan's one-channel sketch cannot work otherwise — rework is local to runtime.rs.
Ruling: Task 2's real-import check may only run if Ollama is already reachable, must use a clearly named temporary model (`hf2ollama-verify-tmp`), must never touch or list-and-modify the user's existing models beyond `/api/tags` reads, and must delete the temp model afterwards. If Ollama is not running, record "unverified" in api-verification.md and continue; Task 10/11 tests rely on wiremock so nothing blocks — a less-verified request shape costs a fix in Task 18's manual acceptance.
Ruling: models — implementers and reviewers on sonnet; Task 9 and Task 11 reviewers on opus (hash verification and file cleanup are the data-safety paths); final whole-branch review on the most capable model (fable).
