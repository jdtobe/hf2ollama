Roost · interface review

Five rounds to a calmer window

The Work tab with an agent running is the busiest screen in the app, so every round redesigns that one. About 25 controls are visible at once today. The rounds below each try a different way of removing them, score the result, and feed the next round. Round 5 is the one being built.

Today (baseline)

Everything is visible all the time

≈ 25 controls Seven in the title row alone, a second bar for the agent, two rows of rail buttons, a footer, and a card per tool call.

Round 1 · Tidy

Same layout, rare actions behind “⋯”

Keep the structure, move Rename, Pin and Delete into one overflow menu, fold the loaded-model status and Unload into the model chip, fold the agent bar into one line.

Works

  • Smallest change; low risk.
  • Title row drops from 7 controls to 3.
  • Delete is already on each rail row.

Still wrong

  • The agent bar is still a second row of controls.
  • Five top tabs plus a text “Settings” tab.
  • Tool cards still fill the transcript.
  • The rail footer still competes with the list.
Round 2 · Quiet chrome

Title only, everything else in the composer

Take the idea further: the header shows just the title. Model, folder, steps and tools become chips in a strip under the input. Navigation becomes Chat, Work, Models and a gear.

Works

  • Header is clean; nav matches the planned Chat › Work › Models › gear.
  • Settings move to a gear.

Still wrong

  • The composer now carries five chips and a button: clutter moved, not removed.
  • The chips crowd the input at 900 px wide.
  • Tool cards are untouched, and they are most of the noise in a run.
Round 3 · Inspector

A details panel on the right

Put every setting in a collapsible right-hand panel: model, folder, steps, tools, loaded status, rename, pin, delete. The transcript and composer stay bare.

Works

  • The conversation itself is as clean as it can be.
  • Room for more settings later (permissions, prompts).

Still wrong

  • At the 900 px minimum, rail + transcript + panel leaves about 380 px for the conversation, so the panel has to be a drawer.
  • Switching model, the most common change, takes an extra open-and-close.
  • A permanent panel is a third column of controls whenever it is open.
Round 4 · Chips and popovers

Show state in the header, edit it in a popover

Keep Round 2's calm header, but put each setting behind the chip that shows its value. Group a burst of tool calls into one line. One “New” button replaces the rail's buttons, and the loaded-model list moves into the Ollama pill.

Works

  • You can see the model and folder without opening anything, and change either in one click.
  • Tool calls collapse to “Used 3 tools”, with live status while running.
  • The rail footer is gone.

Still wrong

  • Folder, steps and tools are three separate chips plus “⋯” in the header.
  • The incognito banner and queued-steering chips add rows.
  • No indication of progress through the step budget.
Round 5 · Chosen

One “Agent” chip, one status line

Round 4 with the leftovers removed. Folder, steps and tools share one Agent chip and popover. A single status line above the composer carries step progress, queued steering and notices. Incognito becomes a small badge, not a banner. The model chip lives with the composer and shows whether the model is loaded.

Works

  • ≈ 13 controls visible, down from about 25.
  • Title row: title, Agent chip, “⋯”. Composer: input, model chip, Stop or Send.
  • Everything has one home; nothing is duplicated.
  • Fits 900 × 640 with room to spare.

Risks

  • Popovers hide some settings (tool toggles, steps) one click deeper.
  • Grouped tool calls need an expand for detail.
  • Real popovers in egui need care at small sizes; verified by layout tests.

If you prefer another round

Rounds 2 and 3 are the ones I would not pick but could be argued for: 2 if you want the plainest possible header, 3 if you expect many more per-session settings. Round 5 is built so that switching is mostly moving existing controls between the same few places (header, composer strip, popover), not a rewrite: the sessions, events and tests underneath do not change.
