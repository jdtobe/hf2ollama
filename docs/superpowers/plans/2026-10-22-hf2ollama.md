# hf2ollama Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a portable Rust desktop app that searches Hugging Face and imports GGUF and supported safetensors models into Ollama through its HTTP API.

**Architecture:** Cargo workspace with `hf2ollama-core` (UI-free async library: Hugging Face client, Ollama client, import pipeline, staging, config) and `hf2ollama-gui` (egui/eframe binary). The GUI sends commands to core over a channel and receives events back; testable view logic lives in pure modules.

**Tech Stack:** Rust 2021+, tokio, reqwest (rustls), serde, thiserror, wiremock and tempfile (tests), sysinfo, keyring, eframe/egui 0.37, Hanken Grotesk and JetBrains Mono fonts.

**Spec:** `docs/superpowers/specs/2026-10-22-hf2ollama-design.md` (visual reference: `docs/design/ui-mockup.html`)

## Global Constraints

- Ollama is reached through its HTTP API only. Never read or write Ollama's store directly.
- TLS is rustls. No OpenSSL dependency.
- `hf2ollama-core` never imports egui. The GUI never makes HTTP calls.
- No `unwrap` or `expect` on I/O, network or parse results in non-test code.
- Defaults: Ollama address `http://localhost:11434`; delete downloaded files after import = **on**; keep partial downloads **7 days**, on; simultaneous downloads **2** (range 1 to 3); auto-dismiss **Never** (options: never, 1 minute, 5 minutes, 1 hour); theme = match system; Hugging Face endpoint `https://huggingface.co`.
- Portable mode: a file named `portable` next to the executable puts settings, history, logs and the default staging folder beside the executable.
- Cancelling a job always deletes its partial files.
- Installed-model delete needs two clicks; the armed state expires after 4 seconds.
- Fit rule: need = size_gb + 1.5; Fits if need <= 0.8 x VRAM; Tight if need <= VRAM; PartialOffload if need <= RAM; else TooLarge; VRAM unknown gives Unknown.
- Hugging Face token lives in the system keychain, never in a config file.
- Design tokens, fonts (Hanken Grotesk regular and semibold, JetBrains Mono regular and medium, bundled with OFL licenses) and component list are as in spec section 7.6.
- Quantization options for safetensors: `f16`, `q8_0`, `q4_K_M`, `q4_0`; `q4_K_M` is the recommended default.
- Every task ends with `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` passing before its commit.

## Review Focus

Inputs the spec implies but its own tests would not otherwise exercise, most likely first. Each has a test in the owning task.

1. **Hostile or odd file paths from Hugging Face** (`../x`, absolute paths, nested folders, Windows drive letters): never written outside the job directory. Task 9.
2. **Repos with no files, only a README, or only unknown extensions**: classified Unsupported with a reason, no panic. Task 4.
3. **Invalid or colliding Ollama model names** (empty, uppercase, spaces, existing name): rejected before download or confirmed before overwrite. Task 11.
4. **HTTP 429, 5xx, and a connection dropped mid-transfer** (Hugging Face or Ollama): a readable error and resumable state, not a hang. Tasks 8, 9, 10.
5. **Paths with spaces and non-ASCII characters, and an app killed mid-download then restarted**: staging works, and the next launch resumes or sweeps the leftover. Task 6.
